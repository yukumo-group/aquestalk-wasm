# AqUsrDic wasm32 port — work in progress

This directory holds the in-progress native wasm32 port of
`libAqUsrDic.so.4.1` (user-dictionary CSV import/export/check).

## Status

**Working:** `AqUsrDic_Check` is ported to wasm32 and matches the native
`.so` on the captured 16-case suite (`node test_check.mjs`).

```sh
./build_check32.sh
node test_check.mjs
```

**In progress:** `AqUsrDic_Import` / `AqUsrDic_Export` (the MARISA writer and
reader).  Their decompiled bodies still contain Ghidra lost-argument/SSE
artifacts; see below.

* Ghidra decompilation dumped to `../decomp_usr/` (474 functions).
* `tools/gen_image.py` embeds the ELF PT_LOAD segments and `.rela.dyn`
  relative relocations.
* `tools/gen_decomp.py` regenerates `src/decomp.c` for the 260 functions that
  are not PLT/exception-landing stubs, including port-specific fixes for the
  decompiler's lost arguments and AqU16/string helpers.
* The Check-only module is built from `src/decomp_check.c` (generated by
  `tools/gen_check.py`), `src/api_check.c`, `src/errors.c`,
  `src/shim.[ch]`, `src/runtime.c` and `src/image.c`.
* The full Import/Export module (`src/decomp.c`) does **not build yet**:
  roughly 20 remaining Ghidra artifacts in the MARISA writer/search internals
  still need manual reconstruction (missing register arguments, SSE vector
  pseudo-types, and a few scope mismatches).

* `src/image.c` is large (1.1 MiB) and the decomp units are generated; they
  can be recreated with the tools.
* The Check-only reading validator is intentionally simplified (kana ranges
  and the accent indicators); the full `FUN_0010c990` reading/accent checker is
  part of the Import/Export work.

## API / behaviour established from the original library

The public API is path-based (`AqUsrDic_Import(pathUserDic, pathDicCsv)` etc.),
so the wasm port will expose a memory-buffer API and implement a tiny
in-memory file system for the paths the library opens:

* `/dic/aqdic.bin` — system dictionary (caller supplied, borrowed)
* `/dic/aq_user.dic` — user dictionary input/output
* `/dic/in.csv` / `/dic/out.csv` — CSV input/output

CSV format (UTF-8, one record per line, no header):

```
surface,yomi,posCode
大江戸線,オーエドセン,5
ＧＤＧＤ,グ'ダグダ,1
```

`Import` reads a CSV and writes a user dictionary; `Export` does the reverse;
`Check` validates surface/yomi/posCode.  Error codes observed from the
original: 100 (bad path), 300–305 (CSV syntax), 301 (surface empty), 303
(reading empty), 200/201/... etc.  The generated `AqUsrDic_Check` body in
`src/decomp.c` documents the 0x12d/0x12f/0x138/0x139/0x13a/0x13b checks.
